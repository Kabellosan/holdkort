# Holdkort: handoff notes

Read this first. It's the source of truth for decisions made so far; the README is the user-facing guide.

## What it is
A phone web app for Captain's idverde crew (Ikast-Brande Kommune contract). Bosses create tasks ("all HA3 Pur in Brande"), assign them to people, and the crew marks each kommune element **Mangler / I gang / Færdig / Blokeret**. Replaces calling each other to say where you've been.

- Live: https://kabellosan.github.io/holdkort/ (GitHub Pages, branch `main`, repo root)
- Repo: `Kabellosan/holdkort`. Everything is in `index.html` (one file, OpenLayers 10 + proj4 + supabase-js from jsDelivr), `sw.js`, `manifest.json`.
- Layout: phone first. At `min-width:1024px` the bottom sheet and the full-screen panels become a left sidebar (`--side`) and the map fills the rest; `wide()`/`sheetH()` keep map fits and the default task rectangle right. Ny opgave (`#pNew`) is wider there, in two columns: types on the left, name/people/Opret on the right. Package chips scroll with the type list (`packBox`, hidden while searching) so they can't squeeze the list off a phone screen. The phone layout must stay unchanged.
- Folding the bottom sheet (2026-10-13, Captain tried dragging the bar down while drawing an area): on phones the bar at the top of the sheet (`#grip`) folds the sheet when dragged down or tapped, leaving only the rows marked `data-keep` (title/back row and the main buttons, e.g. Annullér and Videre) plus "▲ Vis mere"; drag up or tap to unfold. Panes without `data-keep` rows (task list, Liste) don't fold (`can-fold`). Switching pane unfolds it (`pane()` → `fold(false)`).
- Back button (2026-10-15, Captain: Android back left the site): while any popup, panel, sheet step or pin mode is open, one extra history entry sits on top; back (popstate) presses the top layer's own close button (`BACK` list, top first, at the end of `index.html`), so confirm questions like "Stop uden at gemme?" still appear, and pushes the entry again if something is still open. A MutationObserver on `hidden`/`aria-pressed` keeps the entry in step; closing with a button drops it. On the task list (and login) back leaves the site as normal. Escape does the same on computers. New panels/dialogs must be added to `BACK` (`.ask` dialogs are picked up automatically via their `…No` button). Tested in mocked Chromium only, not on a real Android phone.
- Min position (2026-10-21, Captain wanted it at hand on every screen): "◎ Mig" (`#btnMe`, `goMe`) sits under the Foto/Kort switch on phones and computers, in every mode; it starts GPS if it isn't running yet (outside a task) and centres the dot in the map above the bottom sheet. The old "◎ Min position" in the task view's top row was removed. Tested in mocked Chromium only.
- UI language: **Danish**. README and these notes: English.

- **Aerial photo (WMS, MapServer):** `https://kort.ikast-brande.dk/wms`, `SERVICENAME=entreprenoer_udbud`, layer `theme-ortofoto2024`. `theme-orto_foraar_daf` (from the kommune's own map link) does NOT exist in this service.
- **Town/street areas ("⌕ Vælg en by eller en vej", in the area editor and Overblik):** Photon (`osm_tag=place|highway`, kommune bbox) finds the name. Town = everything within 55 m of an OSM building (Overpass `way["building"](around:R)` `out center`, R by place type), the piece at the town point, holes filled. Street = 25 m around the kommune's `element_vej_sti_distribution` lines with that `vejnavn` within 3 km (CQL `ILIKE`, then `LIKE`; Overpass `highway` ways if none), pieces within 150 m linked. Done on a grid on the phone (`outlineOf`, `thinRing`), no geometry library; result is a normal freehand `area`. Cached in localStorage `place:*` for 30 days. Overblik filter (`overFilter`) is app state only, kept across type switches. **Not verified against the live Overpass/Photon/kommune servers from the cloud container (all blocked there); tested with mocked responses.** Dataforsyningen GSearch closes 1 Nov 2026, so it's not used.
- **Plain map (OpenStreetMap):** `ol.source.OSM`, reprojected by OpenLayers into EPSG:25832, drawn paler (CSS filter on `.osm-base`) so status/task colours stay readable. Switch under the zoom buttons: on phones one small button showing the other choice ("Kort" / "Foto"), on computers "Luftfoto / Kort" side by side. Remembered per phone (`localStorage` `base`). No preload and no service-worker caching (OSM tile policy: light use, browser cache only); the "© OpenStreetMap" credit must stay visible while it's shown. Dataforsyningen's skærmkort was skipped because it needs a token.
- **Place search:** Photon (photon.komoot.io) while typing; Nominatim only on Enter / "Søg grundigere" (its usage policy forbids autocomplete). Requests time out (8 s Photon, 10 s Nominatim) with a "Prøv igen" button; answers are memoised in localStorage `searchMemo` (80 entries, 30 days). Town shortcuts (`TOWNS`) show when the box is empty. Typing "… station" adds a Photon `osm_tag=railway:station` query. **DAWA is shut down (HTTP 410).**
- The kommune's `robots.txt` is `Disallow: /`. Therefore: **no nightly server job / scraper** without the kommune's written OK. Phones fetch only when a person opens a task.

## Load on the kommune's server
- Element data per task is stored on the phone (Cache API `elements-v1`); refreshed at most once a day, random 15 s–3 min delay, never 06:00–09:00. "Opdater" forces it.
- Aerial tiles: fixed 256 px grid in EPSG:25832, service worker cache-first, 180 days.
- A task only auto-zooms the first time it's opened; map position is remembered.
- Task areas: a rectangle (`extent` only, `area` null) or a freehand polygon (`area` = GeoJSON Polygon in EPSG:25832, `extent` = its bounding box). The WFS request uses the bbox; elements are cut to the polygon on the phone (`hitsArea`). Max bbox 60 km². If the `area` column is missing, saves fall back to the rectangle. Stored element data carries an area key, so redrawing a task re-downloads it.
- Every fetch must be complete: if a layer fails, the whole fetch fails and the stored data is kept (no partial maps). If the server's GeoJSON says `totalFeatures`/`numberMatched` is more than it returned (a feature cap), the rest is fetched with `startIndex`; if it still doesn't add up, the fetch fails. The real cap on the kommune's server hasn't been checked (it can't be reached from the cloud container).
- Place view (`pPlace`, boss, from the type picker or "Alle typer i …" in a filtered Overblik): every type in a picked town/street via `BBOX` only (no code filter), cut to the outline, cached as `place:<hash of areaKey>` with the once-a-day rules. Counts per type (in a task / done) and tasks reaching in; tapping a type opens Overblik with `overFilter` set to the place; "+ Ny opgave her" passes counts (`newHere`) so those types sort first in Ny opgave. Also opened by "Se alt her" in the new-task area editor (`peek`), with `name` null for a hand-drawn area (`overFilter.drawn` keeps "det valgte område" out of task titles). `pFind` shows "‹ Brug området på kortet" whenever an area is being drawn. While a place view or a narrowed Overblik is open, `overLayer` and `areaLayer` are clipped to the place (`clipShape`, canvas clip on prerender), so long elements or big tasks that touch it don't spill across the map; tasks reaching outside say "Kun delvis her". Place view colours: "Farve pr. type" (default, `place.mode`, localStorage `placeMode`) gives each type a `TYPE_COLORS` colour (`COLORS.ty<i>`, by count order, matching the row swatch and bar; task outlines hidden) or "Status" (as Overblik). Tapping a type row highlights it (others grey, `place.focus`) and zooms; "Åbn" opens Overblik for the type. Tapping an element marks it (`place.sel`) and toasts its type, size and tasks. Back buttons step back one level: narrowed Overblik → "‹ Alle typer her" (place view), place view from "Se alt her" → "‹ Tilbage til området" (area editor with the same shape). Shares `overSrc`/`areaSrc`/`filterSrc` with Overblik; `closeOverview()` also closes it. Tested with mocked WFS only.
- Overblik (boss): one type for the whole kommune via `elementkode IN (...)` with no bbox, cached as `type:<code>` with the same once-a-day rules. Status per element comes from the tasks covering it (done > blocked > doing > todo); purple = in no task. Each task area gets an outline colour from `TASK_COLORS` (by created_at order, avoiding the status colours), shown as a stripe in the task list; tapping a task focuses it.
- Whole-kommune task for rare types (2026-10-21, Captain: saltværn (UD84a) are a few tiny spots across the kommune and a task area is max 60 km²): in an unnarrowed Overblik with ≤ `OVER_ALL_MAX` (300) elements, "+ Ny opgave med alle N …" builds `newSpots` straight from `overSrc` (clones without the overview's `_` props) and opens Ny opgave as a spots task, so phones fetch it with `fetchSpots`. "▭ Eller tegn et område" (`btnOverArea`) keeps the old area flow; narrowed or bigger types use it as before. Kommune elements added later aren't in such a task. Tested with mocked WFS only; the real count isn't known (kommune server blocked from the container).
- Overblik for a package (2026-10-15, Captain asked): package chips at the top of "Overblik: vælg type" (`typePacks`, hidden while searching) open `openOverview(codes, packName)`; `over.codes`/`over.pack` replace `over.code`. Each type is still fetched and cached alone (`type:<code>`), missing ones one at a time with "x af y typer"; any failure fails the open/refresh. Elements count for a task only if the task has their type (`cs`). Extra mode "Typer" (only for 2+ types, `over.tcol` in package order, done fades, 🚧 kept, task outlines hidden); legend shows done/all per type. Default stays Status. "+ Ny opgave" passes all the package's codes. Tested with mocked WFS only.

## Backend: Supabase
- Project `rvfwmmctqndfqvbuuoyi` (org "Kabellosan's Org", region eu-west-1), connected via the Supabase connector.
- Publishable key is in `index.html` (public by design). Never put the service_role key in the repo.
- Tables: `tasks` (id, name, codes[], extent, assignees[], created_by, created_at, archived, summary, area), `progress` (task_id, element_id, status todo|doing|done|blocked, note, reason (only for blocked: Bil parkeret / Vejarbejde / Andet), worker, updated_at; PK task_id+element_id), `people` (name, role).
- Trigger `progress_day_only` truncates `updated_at` to the day **in the database**.
- RLS: see "Login" below. `supabase/login_lock.sql` was run on 2026-10-11, so anon (the public key alone) can read or change nothing; only the three logged-in accounts can. Delete on `progress` only when its task is archived; no deletes on tasks/people.
- **Login (2026-10-11):** codes are checked by Supabase Auth, not in `index.html`. Three shared accounts (`ROLE_EMAIL`: `koordinator@`/`udfoerende@`/`hjaelper@holdkort.example`, reserved domain so no reset mail can reach anyone), password = the code, lowercased. `signIn` tries crew, boss, helper in turn. `public.hk_role()` maps the JWT email to boss/crew; RLS lets any role read and mark progress, only boss write tasks/packages/remove people (crew may only upsert its own crew row). Logout uses `signOut({scope:"local"})` (shared account: global would log out every phone). A phone with a stored user but no session is sent to login with its name kept; a getSession error (offline) keeps it logged in. `progress_trash` (trigger `progress_to_trash`, purged after 14 days, no RLS policies) keeps marks deleted by closing a task. SQL: `supabase/login.sql` (rules + trash), `supabase/login_lock.sql` (drops the anon rules; run only after the accounts exist and the app is live).
- Realtime on `tasks` and `progress`.
- `packages` (id, name, codes[], created_by, created_at): named groups of types bosses pick in Ny opgave (`packChips`, also in `pShow`; 2026-10-19, Captain wanted to take types out of Fast belægning: tapping a package not yet in ticks all its codes and opens its types under the chip as tickable rows; the chip shows "· 7 af 8" when partial; tapping it again folds it; "Fjern hele pakken" in the box removes all; `packNames` names a package missing 1–2 types (packages of 4+) "Fast belægning uden kantsten", also in titles and task rows), save from ticked types ("Gem som pakke") and edit/delete in the Pakker panel. RLS anon: select/insert/update/delete. Seeded 2026-10-06 with Fast belægning (FB*), Løs belægning (LB*), Hæk og pur (HA*) from the kommune's code prefixes; on 2026-10-13 one package per kommune map folder was added (Træer, Græs, Sport og leg, Afvanding, Bevoksning, Buske og hæk, Bygværker, Blomster, Klatreplanter, same codes as `FOLDERS`). Package names also shorten long type lists in task rows (`packNames`/`shortCodes`). SQL in `supabase/packages.sql`.
- Task map with several types (2026-10-12, user expected type colours there): a "Status / Farve pr. type" switch under the progress bar, shown only when `codes` has more than one type, remembered per phone (localStorage `workMode`, default status). Type mode colours each element by its type (`workTcol`, `TYPE_COLORS` in the order the types were ticked, green/yellow/red last via `WORK_TY` so they aren't read as status); done ones fade, blocked keep 🚧; a legend shows each type's done/total and Liste gets a colour stripe. Picking spots stays blue/grey.
- `tasks.elements` (text[], null = every element of the task's types in its area): hand-picked element ids (`<layer short>:<ogc_fid>`). The phone keeps the whole area's data (`taskAll`) and shows only the picked ones (`onlyPicked`); bosses pick in the `pPick` pane ("☝ Steder", or "Kun udvalgte steder" when creating). Overblik counts a task only for its picked elements.
- `tasks.spots` (jsonb, null = area task; SQL in `supabase/spots.sql`): a task made by tapping spots ("+ Ny opgave" → `askNew` → "☝ Tryk på stederne", pane `pSpots`, `startSpots`/`spotTap`, reuses `pick` with `pick.spots`). Captain asked 2026-10-12: the koordinator wants a task of just the spots Jacob does by hand (where the hako machine can't go), the same elements also being in the machine's area task. Before picking a new task it asks "Vis alt" or "Vælg typer eller pakker" (Captain, 2026-10-13; `askShow`, panel `pShow` reusing `codeChecks` and package chips, last choice in localStorage `spotShow`); `pick.show` (Set or null) hides other types on the map (`spotHidden`, style null, not tappable) but spots already picked always show; "Skift" in `pSpots` changes it, also when changing an existing task (which starts at Vis alt). Elements are coloured while picking (Captain, 2026-10-13: "instant overview of what things are", "always coloured no matter the view"): `spotColors` fills `pick.tcol` (`pickKey` → `TYPE_COLORS` key, in the order things turn up on the map, kept while panning; `SPOT_TY` skips the blues), `pickLegend` shows the key. With types chosen: per type; with Vis alt: per group (`groupOf`, the kommune folders, else "Andet"), since there are too many types; picked spots are thick blue on top. In `pPick` (spots in an area task with 2+ types) the picked ones keep their type colour and the rest go grey ("Farvet er med, grå er ikke"). One type alone stays blue/grey. The task view keeps status as the default colour (its Status / Farve pr. type switch). While picking, the map fetches every layer by `BBOX` of the view (only when the view is ≤ 5 km², `SPOT_VIEW`, once per place); with types chosen it asks `elementkode IN (…) AND BBOX` instead, from views up to 60 km² (`SPOT_VIEW_TYPES` = `MAX_AREA`; Captain found 5 km² too close, 2026-10-13), with no margin when the margin would pass 60 km², and names pur/fortov via `nameByStreet` since roads aren't in that answer; `pick.got` remembers `{ext, codes}` so a Vis alt fetch covers any filter; a tap takes the smallest element under the finger. Each spot is `{id, code, box, street}` (kommune element) or `{id:"egen:<uuid>", name, xy}` (own point, "📍 Eget punkt", a Point feature with `_own` = name, no `elementkode`). `elements` = the ids, `codes` = the kommune spots' types, `extent` = bbox of spots + 40 m, `area` null; no outline is drawn for these tasks (task view, Overblik, place view). Phones fetch them with `fetchSpots`: picked codes AND an OR of `BBOX`es around the spots (merged within 50 m, 30 per request), falling back to the codes in the whole kommune; the tapped features are put in the element cache on create/save, so the creator's phone asks nothing more. `saveTask` says so if the column is missing. **Not verified against the live kommune WFS (OR of BBOXes) from the cloud container; tested with a mocked WFS.**
- **Who a task is for (2026-10-21, Captain wanted to add someone to an existing task):** the task view shows "👥 Alle" or the names (`workWho`, everyone sees it); koordinatorer get "Ret hvem" (`btnWho`) → dialog `askWho` with the same name chips as Ny opgave (`peopleChips`, shared with `renderAssign`; names on the task but no longer on the team stay listed), saved straight to `tasks.assignees`. Udførende can't change it (their own tasks are for themselves). The dialog warns that "Alle" leaves out Hjælpere. Tested with the mocked harness only.
- `people.removed` (date, null = on the team; SQL in `supabase/people_removed.sql`): a boss removes someone from the Holdet tab after a confirm screen. Rows are never deleted, so Historik names stay. Removing also strips the name from active tasks' `assignees` (a task left empty becomes "Alle"; the confirm screen warns). A removed name can't log in with the crew code (case-insensitive match), and a logged-in phone is logged out once nothing is pending. "+ Tilføj person" inserts a crew row or clears `removed`.
- `element_log` (id, element_id, code, task_id, day, done, status, reason, note, photo): append-only per-element log with `worker` name (user chose "names for bosses" on 2026-10-06; Historik shows names only to bosses), survives archiving. Written on Send for every status change (status/reason; `done` = newly done, feeds last_tended), a new note, or a photo; if the status/reason/worker columns are missing it falls back to the old done/note/photo lines; un-doing within a day deletes that task's done line (RLS allows delete only for day >= yesterday, insert only for today ± 1). View `last_tended` (element_id, code, last_day; security_invoker) feeds "Sidst passet" in the element pane/list (RECENT = 14 days warning) and Overblik's "Sidst passet" mode (AGES buckets). SQL in `supabase/element_log.sql`.
- Billede (2026-10-15, Captain asked to reach the camera app directly): on touch phones (`pointer:coarse`) the 📷 Billede button asks "Tag billede" (`#photoCam`, `capture="environment"`) or "Vælg fra galleri" (`#photoIn`) in the `askPhoto` dialog; computers go straight to the file picker. Both inputs share one handler. A photo taken with the camera gets "💾 Gem på telefonen" in its toast (8 s, `keepAct`, also for note-thread photos): a web page can't save to the gallery by itself, so iPhones get the share sheet ("Gem billede" → Fotos) and other phones download the original (Downloads in the gallery). Gallery picks don't get it (already on the phone).
- Storage bucket `photos` (public, jpeg ≤ 3 MB, insert-only for anon). Photos are re-encoded on the phone via canvas (strips EXIF/GPS), kept in Cache API `photos-v1` with the pending mark until Send, path `<day>/<uuid>.jpg`. Viewed in Historik (one element, all tasks) or "📷 Billeder" in the task pane (`showTaskPhotos`: all `element_log` photos and notes for the open task plus unsent photos, reuses `pHist`). `loadTaskMedia` marks elements with photos (`taskMedia`, 📷 in Liste) and puts the count on the button. **Note/photo marks (2026-10-15, Captain asked):** a small 📝 / 📷 badge above elements (`badgeStyle`, `badgeText`): in a task for its current note (`eff(id).note`, sent or pending; gone after "Ikke aktuel mere") or its photos (`mediaMark`); in Overblik and the place view for the active tasks covering the element (`progressFor` also returns `noted`/`photos` sets, from `progress.note`, pending rows and `element_log` photos; feature prop `_m`). Tapping a marked element in Overblik/place view opens its Historik (read-only, every task) instead of the toast, since `showNotes` needs an open task. The element pane's 📝 Note button shows `📷 n` (`noteN`). Tested with mocked Supabase only.
- **Part of a long element (2026-10-12):** `progress.parts` (jsonb, `[{day, p:[[x,y],…], r, m}]`, EPSG:25832) holds stretches done on one line or area ("📏 Stykke" in the element pane, `pPart`/`partEd`). The worker taps where they started and stopped: lines use the stretch along the line between the two taps (`measureAt`/`stretch`; a third tap moves the stop), areas use a band of radius `r` around the taps (`capsule`, clipped with Sutherland–Hodgman in `clipRing`; one tap = circle; default r ≈ the area's width, 2A/perimeter). Drawn green on top of the element (`partStyle`) unless it's Færdig; share done via `partSize` (lines exact, areas on a sample grid) cached per feature (`partShare`). Saving a stretch sets Mangler → I gang. `element_log.part` `{m, of, u}` logs each new stretch (Historik). Parts are compared by `partKey` because jsonb reorders keys. The button is hidden until the column exists (`checkParts`). `supabase/parts.sql` was run on 2026-10-12; it also rewrites `progress_to_trash` to name its columns (it copied `old.*` by position). Not shown in Overblik yet. Tested with mocked WFS only.
- **Marking clears the selection (2026-10-15, Captain asked):** tapping Mangler / I gang / Færdig (or a Blokeret reason) sets the status for every marked element, clears the marks and closes the element pane (`markAndClear`), so Næste ▸ in the task pane is right there. A 6 s toast says what was set with "↶ Fortryd" (`toast(t, ms, {label, fn})`): unsent, it puts the outbox back exactly as it was; already sent (auto-send), it sends the old status back. Either way the same elements are marked again. Without GPS, Næste starts from the last marked spot (`lastAt`). Note, photo and Stykke don't clear. Tested with the mocked harness only.
- **Færdig colour (2026-10-19, Captain: done looked only paler blue in Farve pr. type):** Færdig is idverde's lime brand green `#bfd830` (from Brandfetch's idverde.dk brand colours; their site is blocked from the container) with a dark olive edge (`DONE_EDGE` / `--done-edge` `#3d4f00`) so it reads on the pale OSM map and the photo; `--done-ink` `#4a6000` for text on white. ## Decisions the user made (don't undo without asking)
- **Individual elements**, multi-select by tapping more elements. An earlier auto-grouping into "stops" was rejected.
- **Login = name + shared code**, roles boss/crew/helper, shown as **Koordinator / Udførende / Hjælper** (`ROLE_NAME`; user renamed Chef→Koordinator and asked for the helper tier on 2026-10-11 as a showcase for the bosses). A "Betroet" role (crew who create tasks for themselves) was built and reverted the same day: the user wanted login codes, not a per-person setting. Instead (2026-10-11) the Udførende code itself may create tasks for themselves only (`canCreate`/`canManage`; `assignees` = [own name], no Overblik, no package editing, no "Se alt her") and change/close only tasks made with that login (`tasks.made_by_crew`, set by trigger `tasks_made_by`, never changed). Enforced by RLS in `supabase/own_tasks.sql` (`hk_self_task`); `hk_role()` there returns `helper` for the Hjælper account, which can't create. Codes are the passwords of three Supabase accounts (see Login above); the user asked for 7430 in the codes. UI text says "koordinator" where it used to say "chef". The name is still trust-based.
